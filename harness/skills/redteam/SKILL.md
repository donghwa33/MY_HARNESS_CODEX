# 레드팀 검토

## 목적
결론이 틀릴 수 있는 경로를 찾아 기록하고, 핵심 숫자를 다른 방법으로 재계산해 일치 여부를 확인한다.

## 절차
1. 지정된 파일만 읽는다 (README, work/AGREEMENT.md, DECISIONS.md, FINDINGS.md, src/, outputs/tables/). 이전 대화의 해석을 가정하지 않는다.
2. 결론을 깨뜨릴 대안 가설을 3개 이상 쓴다. 각각 반증에 필요한 데이터와 현재 가능 여부를 적는다.
3. 코드 버그를 점검한다: 필터 순서, 조인 손실, 날짜 경계(포함/미포함), 집계 단위, 보정 이중 적용, 하드코딩된 숫자, UI 에서의 재계산.
4. README 필수 조건과 AGREEMENT 성공 기준의 충족 여부를 기준별로 판정한다.
5. 핵심 숫자 최대 3개를 기존 코드를 보지 않고 다른 방법으로 재계산해 src/recheck.py, outputs/tables/recheck.csv 에 남긴다.
6. UI 가 있으면 서버 실행 상태와 스모크 테스트 결과를 확인하고, 화면 숫자와 outputs/ 표가 일치하는지 본다.
7. 모든 지적을 work/REVIEW.md 에 R-번호로 쓴다. 판정 칸은 비워두고 사람이 채운다.

## 하지 말 것
- 기존 코드를 수정하지 않는다 (recheck.py 만 새로 쓴다).
- 총평을 쓰지 않는다. 지적 사항만 쓴다.
- 지적이 없다고 쓰지 않는다. 최소 3개는 찾고, 사소하면 사소하다고 표시한다.
